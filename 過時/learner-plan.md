## 0. 前提（2026-09-26 使用者確認）

1. **使用者**：你自己，N5 大致學完。完全沒學過的新手不是這次的目標，所以不做「程度前測」。
2. **每天時間**：通常 30 分鐘，最多 1 小時。所以**一篇故事（約 12 個新字）走完「下一步」流程約 30 分鐘＝一天的基本份量**，時間多的日子做到兩篇；流程設計以「一篇 30 分鐘內走得完」為準。
3. **一課的大小不變**：仍是 40–80 字、3–7 篇。這次只改「怎麼帶著學」，不改份量。
4. **會話短劇的聲音**：每個說話人用不同的聲音，不唸說話人的名字。
5. **試點複習字**：你沒有指定，由 skill 從舊課挑。

## 2. 設計決策

### 決策 1：篇的歸屬不改 schema，由故事標記推算

單字「屬於第幾篇」＝它在故事裡**第一次出現的那一篇**。引擎載入時從 `{{key|…}}` 算出來，不在 `vocab.json` 加欄位，這樣舊課也能直接用。
克漏字、排序題的篇別＝該文法點第一次被 `[[g#]]` 標到的那一篇。讀解題已經有 `st`。

### 決策 2：完成狀態大多用現有紀錄推算，只新增「讀過」

| 狀態 | 怎麼判斷 | 資料來源 |
|---|---|---|
| 讀過 | 流程第 1 步按「讀完了」 | **新增** `progress.stories["<課id>/<篇號>"] = {read: 日期}` |
| 跟讀過 | 流程第 2 步按「跟讀完了」（不強制錄音） | 同上，`shadow: 日期` |
| 單字練過 | 本篇新字都評分過至少一次 | 現有 `progress.vocab[key].seen` |
| 文法練過 | 本篇新文法點的克漏字都答過 | 現有 `progress.quiz` |
| 讀解做過 | 本篇 5 題都答過 | 現有 `progress.quiz` |

`assets/store.js` 只**新增欄位**（`stories`、`exams`），讀舊資料時補成空物件；不改既有欄位，所以不用做版本轉換（`v` 仍是 1）。新增 API：`markStory(lessonId, n, step)`、`getStory(lessonId, n)`、`setExam(lessonId, score)`、`getExam(lessonId)`。

### 決策 3：複習字沿用同一種標記，由驗證器分辨

故事裡的 `{{key|課文形|讀音}}`：
- `key` 的 `lessons` **含**本課 → 本課新字（跟現在一樣）
- `key` 的 `lessons` **不含**本課、但在 `vocab.json` 裡 → **複習字**

好處：標記語法不變，所以「四處解析要一致」的那四個地方（`generate-audio.py`、`build-audio-check.py`、`validate-lessons.py`、`lesson-engine.js`）都不用改解析。
要改的只有：
- `validate-lessons.py`：原本「標記的 key 不含本課」會報錯，改成「key 必須在 `vocab.json`；不含本課的算複習字」。另外提醒「每篇複習字 0 個」「全課複習字 < 5 個」。
- 引擎：複習字用另一種樣式顯示（例：虛線底＋小「復」字），點開一樣是單字卡，卡上寫「第 N 課學過」。複習字**不進**本課單字表和本課測驗，只算在跨課複習裡。
- 難度規則：複習字**不算新東西**，所以可以跟新字或新文法放同一句。

### 決策 4：聽寫用單字與例句，不用故事句

故事目前是「一段一個音檔」，沒辦法單獨播一句（句子級音檔這次不做）。所以聽寫出兩種題：
1. **單字聽寫**：播單字音檔 → 打假名 → 對照 `reading`。資料現成。
2. **例句聽寫**：播 `ex` 的音檔 → 打假名 → 對照新欄位 `exKana`。

`vocab.json` 新增**選填**欄位 `exKana`（例句的全假名寫法，標點照原句）。沒有這欄的字只出單字聽寫。
驗證器檢查 `exKana` 全是假名與標點，且句數和 `ex` 一樣。

### 決策 5：打字作答怎麼判對錯

- 比對前統一：片假名轉平假名、去掉空白與標點、長音「ー」保留。
- 答完照 Anki 流程：顯示正確答案與你打的（不一樣的字標紅）→ 你自己評分。系統只給「對／不對」的提示，**評分權留給你**，因為手機輸入法常常選錯字。
- 打字模式是單字測驗裡的新選項「中→日（打字）」「聽寫」，不取代原本的選擇題。

### 決策 6：會話短劇沿用 `stories[]`

新增一篇 `stories[]`，加兩個欄位：
```jsonc
{ "title": "会話：卒業式のあとで", "kind": "dialogue",
  "speakers": ["私", "先生", "私", ...],     // 跟 paragraphs 一樣長，一行一個說話人
  "paragraphs": ["先生（せんせい）、ありがとうございました。", ...],
  "translation": ["老師，謝謝您。", ...] }
```
- 說話人**不寫進段落文字**，所以音檔不會唸出人名。
- **每個說話人一個聲音**：故事層加 `"voices": {"私": "ja-JP-Neural2-D", "先生": "ja-JP-Neural2-C", "友達": "ja-JP-Neural2-B"}`。聲音只能從 `try-voices.py` 那組挑（Neural2-B／C／D、Wavenet-A／C），同一篇裡不同人不能用同一個聲音；skill 依人物性別與年齡分配，你可以在確認時改。
- **音檔 key 要帶聲音**：同一句話由不同人說會是不同音檔，所以對話行的音檔 key 用 `@<聲音>:<句子>`（一般段落的 key 不變）。這會動到「四處要一致」的音檔 key 規則，四個地方要一起改：`generate-audio.py`（`clean_story_json` 產生帶聲音的項目、`synthesize` 用該聲音）、`build-audio-check.py`（列出並標說話人）、`validate-lessons.py`（音檔覆蓋率檢查）、`lesson-engine.js`（`play` 查帶聲音的 key）。
- 內容規則：**不加新字、不加新文法**，只重組本課的字與文法；依關係用普通形或です・ます（朋友普通形、老師敬語），這正是故事裡較少練到的部分。
- 讀解題可以出在對話上（`st` 指到它）；它不算進「篇數 ≈ 字數 ÷ 12」。
- 引擎：`kind:"dialogue"` 時左邊顯示說話人，同一人的行靠同一邊。

### 決策 7：文章文法題的資料格式

```jsonc
"passageQuiz": [
  { "id": "pq-01", "st": 3, "para": 1,          // 取第 3 篇第 1 段
    "text": "…友達（ともだち）に（１）、…（２）…",   // 段落改寫成有空格的版本，保留注音標記
    "items": [ { "o": ["話してもらい","話しておき","話してしまい","話していき"], "a": 0, "g": 5 }, … ] }
]
```
- 每課 2 題組，每題組 3–4 格，空格優先挖本課文法點，也可挖接續詞（`けれども`、`それで`）。
- 驗證器：把正解填回空格，去掉標記後必須**等於**原段落的純文字，這樣題目和故事一定對得上。干擾項規則沿用克漏字（清單內文法、優先「對比」欄）。
- 進度 key：`<課id>/pq-01#1`（題組＋第幾格），照「修題不改 id」的規則。

### 決策 8：單課小考在執行時組題，不另存題目

照 `docs/mock-exam-plan.md` 的分離原則，新檔 `assets/mock-exam.js`，**不塞進 `lesson-engine.js`**。
- 10 題，從本課現成資料抽：漢字読み 2、表記 2、文脈規定 2（`ex` 挖掉該字，干擾項＝同詞性的本課字）、文法克漏字 2、排序 1、讀解 1。
- 做完顯示分數、錯題與解說；只記最高分（`setExam`），首頁卡片顯示。
- 入口：「下一步」流程最後一篇完成後出現「本課小考」，故事分頁最上方也有按鈕。不新增第 5 個底部分頁。
- 之後做跨課模考（`lessons/mock-exam.html`）時直接重用這支。

### 決策 9：JLPT 參考等級

`vocab.json` 新增選填欄位 `jlpt`：`"N5"`…`"N1"`，或 `"外"`（清單外、生活用語）。
- **只是參考**：JLPT 官方 2010 年後沒公布單字表，由 skill 依舊版出題基準與常見 N5–N1 單字表判斷，確認字表時列給你改。
- 確認字表時，N3 以上與「外」的字會**特別標出來**，附一句「故事可能要硬塞，要不要換掉」，由你決定。
- 引擎：單字卡與單字表顯示小標籤；總表可以依等級篩選。

### 決策 10：自然度審查與回報

- **審查**（skill 新步驟，寫完故事、建檔前）：另派一個助手，只給它日文故事、對話與「日本人會不會這樣說」的標準，要它列出可疑句子與理由，**只挑錯、不改檔**。主流程逐條判斷要不要改，把結論寫進步驟 2 的確認清單給你看。
- **回報**（引擎）：每段右上角「⋯」→「這段怪怪的」，寫一句備註，存進 `setNote("para", "<課id>/s3p2", 文字)`。設定裡的「我的回報」列出全部，並有「複製清單」按鈕，貼給 Claude 就能修。

### 決策 11：首頁分區

`build-index.py` 改成四區：**開始學**（引擎課，新到舊，卡片多顯示「完成 3／6 篇」「小考最高 8／10」）、**每日複習**（現有的今天要複習）、**工具**（複習中心、文法查詢、單字總表、動詞工具）、**舊版**（`日文70單字學習器`）。

## 5. 風險與對策

| 風險 | 對策 |
|---|---|
| 動 `assets/` 影響所有引擎課 | 每階段回歸測 6 個頁面；先匯出進度當對照 |
| `store.js` 加欄位讀到舊資料出錯 | 只新增欄位、讀取時補預設值；匯出→匯入測一次 |
| 流程太多步反而煩 | 流程只是「建議」：每步都能直接跳過，也能照舊用底部分頁自由練 |
| JLPT 等級判斷不準 | 標「參考」，你可以在字表確認時改；不拿它當任何規則的硬條件 |
| 打字判對錯被輸入法選字干擾 | 系統只提示、不自動評分（決策 5） |
| 複習字讓故事變難 | 複習字限每篇 1–3 個、不算新東西；驗證器照舊量新字密度 |
