# 模考產生器 規劃

> 狀態：**規劃中，尚未動工**。這份是動工前的設計文件，決定「做什麼、怎麼做、分幾階段」。
> 起點是 `docs/lesson-authoring.md` 的「JLPT N4 文字・語彙題型參考」那一節（2026-09-12 記下的構想）。
> 真的開工後，把「已完成」的部分搬進 `docs/architecture.md` 與 `docs/changelog.md`，這份文件只留還沒做的。

## 1. 要做什麼

一個**跨課、綜合複習**的模擬考頁面：吃 `data/vocab.json`（目前 140 字，之後每加一課就變多），
用 JLPT N4「文字・語彙」的題型出一份考卷，可以重複作答、記錯題。

**不做的事**（寫下來，免得做著做著就越界）：

- 不改 `assets/lesson-engine.js` 與 `assets/lesson.css`。動這兩支要回歸測試每一個引擎課（見 `CLAUDE.md`），
  而模考頁跟引擎課的結構差太多（沒有故事、沒有文法對照表），套引擎等於在引擎裡加一堆 `if`。
- 不改 `data/lessons/*.json`。模考不綁單一課程。
- 不放任何補習班／市售教材的實際題目原文進 repo（版權不是我們的）。題目一律自己生成或自己寫。
- 不碰 `lessons/日文70單字學習器.html`。

## 2. 為什麼另開，不塞進 `new-lesson` skill

`new-lesson` 有 12 個步驟，模考用得到的只有最後的驗證與發佈。前面的步驟 1（讀單字照片）、
步驟 2（確認字表）、步驟 4（寫故事）、步驟 6（建 `data/lessons/<id>.json` 與薄殼）、
步驟 7（新字進 `data/vocab.json`）、步驟 8–9（產語音）全部不適用——
`new-lesson` 是「新單字 → 一課」，模考是「舊單字 → 一份不綁課的考卷」，資料流方向相反。

另外 skill 靠開頭 `description` 判斷何時啟動，兩種語境（「我拍好單字了」vs「出一份複習考卷」）
塞同一段描述會讓觸發判斷變糊。`SKILL.md` 已經 196 行，再塞第二種模式會讓每次做一般課程都要讀不相關的內容。

## 3. 題目的兩種來源

網站是 GitHub Pages 純靜態、沒有後端，**網頁在執行時不可能呼叫 AI**
（要呼叫就得把金鑰寫進 JS 公開出去，`CLAUDE.md` 也禁止金鑰進 repo）。
所以題目只有兩種來源：

| 來源 | 意思 | 題目量 | 需要新資料檔嗎 |
|---|---|---|---|
| **程式即時算** | 頁面上的 JS 讀 `data/vocab.json`，用規則當場組題 | 無上限，每次隨機 | 不用 |
| **事先寫好的題庫** | AI／人先寫好題目 → 存成 JSON → commit → 網頁隨機抽 | 固定（寫幾題就幾題） | 要 |

兩者不衝突，是同一個頁面的兩種題目來源。

## 4. 五種題型逐一評估

`data/vocab.json` 每筆欄位：`key / dict / reading / pos / zh / form / ex / lessons`。
目前 140 筆，其中 **122 筆 `dict` 含漢字**、**140 筆都有 `ex` 例句**。

| 題型 | 來源 | 現有資料夠不夠 |
|---|---|---|
| 漢字読み | 程式即時算 | 夠（`dict` + `reading`） |
| 文脈規定 | 程式即時算 | 夠（`ex` + `pos`） |
| 表記 | 事先寫題庫 | 不夠：缺「形近漢字」資料 |
| 言い換え類義 | 事先寫題庫 | 不夠：缺改寫句 |
| 用法 | 事先寫題庫 | 不夠：缺誤用例句 |

### 4.1 漢字読み（程式即時算）

- **題幹**：用 `ex` 例句，把目標詞標底線（比只給單字更接近真題）。
- **答案**：`reading`。
- **干擾項規則（已實測，見 4.3）**：
  1. 第一順位：**其他單字的真實讀音**，條件是「送り仮名一致」且「拍數差 ≤ 1」。
  2. 湊不到 3 個時，才用**小幅變形**補：清濁互換、去長音。變形只動送り仮名以外的部分，
     且不得撞到 `data/vocab.json` 裡任何既有讀音。
  3. 還是湊不到 3 個 → 這個字這次不出題（換一個字）。
- **選項必須去重**（實測發現同一題會抽到兩個相同選項）。

### 4.2 文脈規定（程式即時算）

- **題幹**：`ex` 例句，把目標詞換成 `（　）`。
- **答案**：目標詞。
- **干擾項**：同 `pos` 的其他單字。
- **詞性分布**（決定干擾項湊不湊得到）：名詞 46、自動詞 19、他動詞 18、い形容詞 15、サ變 8、副詞 6、
  な形容詞 3，其餘各 1–5。副詞與な形容詞太少，干擾項會一直重複同幾個字。

### 4.3 實測數據（原型跑過，不是估計）

**漢字読み的干擾項，試了三種做法：**

| 做法 | 122 個含漢字單字裡湊得到 3 個干擾項的 | 品質問題 |
|---|---|---|
| 只用規則變形（濁清、長短、促音） | 68 | 差。造出「しょっくりょうひん」「もどうす」這種一看就不是日文的選項，太好猜 |
| 只用別的單字的真實讀音（同拍數） | 120 | 中。四個選項都是真日文，但彼此不相干（`汚れる` 的選項出現 `ほがらか`），送り仮名一看就露餡 |
| **混合：真實讀音（送り仮名一致）優先，不足才小幅變形** | **102**（100 純真實 + 2 需補變形） | **好**。例：`怖い` → こわい／にがい／ぬるい／ふかい；`太る` → ふとる／やせる／ぬる／のこる |

**採用第三種**，剩下 20 個湊不滿的字，那一輪就跳過不出。

**已知弱點**：名詞沒有送り仮名（`tail` 是空字串），所以名詞題的干擾項是不相干的詞
（例：`興味` 的選項出現 `たおれる`），偏簡單。目前無解——要修得靠「同一個漢字的其他讀法」資料，
`vocab.json` 沒有。列為已知限制，階段二再看要不要補資料。

## 5. 資料結構

### 階段一：不需要新資料檔

漢字読み與文脈規定都從 `data/vocab.json` 當場算，沒有題目檔。

### 階段三才需要：`data/exam-bank.json`

事先寫好的題目放這裡，**不要放進 `data/lessons/`**——`validate-lessons.py` 會掃那個資料夾
並用課程 schema 驗，放進去會直接報錯。

```json
[
  { "type": "hyoki",   "s": "この店はやすいです。", "target": "やすい",
    "o": ["安い","高い","低い","易い"], "a": 0, "expl": "價格便宜用「安い」。「易い」是容易。" },
  { "type": "iikae",   "s": "この部屋はきれいじゃありません。",
    "o": ["汚いです","狭いです","広いです","新しいです"], "a": 0, "expl": "…" },
  { "type": "youhou",  "target": "そろそろ",
    "o": ["そろそろ帰ります。","そろそろ食べました。","…","…"], "a": 0, "expl": "…" }
]
```

- `type` ∈ `hyoki`（表記）／`iikae`（言い換え類義）／`youhou`（用法）
- 單一檔案即可，題目多到難管理再拆成 `data/exam/<set>.json`

## 6. 頁面設計

### 檔案

- `lessons/mock-exam.html`：**獨立頁**，不是引擎課薄殼。
  參照 `lessons/日文單字總表.html` 的模式（自己的 CSS、`fetch ../data/vocab.json`、
  深色模式與字級設定、`← 回目錄`）。
- 檔名用英數連字號（`CLAUDE.md` 硬性規定），`<title>` 用中文：`N4 模擬考（跨課複習）`。
  `build-index.py` 掃 `lessons/*.html` 讀 `<title>`，所以它會自動出現在首頁目錄。

### 一份考卷

- 預設 20 題，可選 10／20／35 題。
- 階段一的比例：漢字読み 10 題 + 文脈規定 10 題（另外三種還沒有題目）。
- 階段三補齊後改成接近真題的比例：漢字読み 7、表記 5、文脈規定 8、言い換え 4、用法 4（合計 28）。
- 作答方式沿用引擎課現成的四選一寫法（`gqRender()` 那套：`o[]` 渲染成按鈕、點了顯示對錯與說明）。
  這是**照抄寫法**，不是共用程式碼——不動 `assets/`。

### 計分與紀錄（localStorage）

前綴 `mockexam:`（慣例：引擎課用 `<id>:`、單字總表用 `vocabtable-`）。

| key | 內容 |
|---|---|
| `mockexam:theme` / `mockexam:fs` | 深色模式、字級（跟其他頁一致） |
| `mockexam:wrong` | 錯題紀錄。程式生成題用穩定 key（`kanji:<單字key>`、`bunmyaku:<單字key>`），題庫題用 `bank:<索引>`。不能用題號，因為每次出題順序都不同 |
| `mockexam:last` | 最近一次成績與日期 |

有了 `mockexam:wrong` 就能做「只考錯過的」複習模式，跟引擎課的「答錯待複習」一致。

## 7. 跟現有系統的連動

| 項目 | 要不要處理 |
|---|---|
| `build-index.py` | 要跑一次，新頁才會進 `index.html`。日期用最後 commit 日 |
| `validate-lessons.py` | 新頁**一定要有 `<a href="../">← 回目錄</a>`**，否則 `check_backlinks()` 報錯、`validate-on-publish` hook 會擋下發佈 |
| `.github/check-console.mjs` | 自動掃 `lessons/*.html`，新頁會被納入。console 有 error 就 CI 變紅 |
| `generate-audio.py` / audio-check | **不用動**。階段一不做語音題 |
| `assets/vocab-table.js` | 不用動 |
| `docs/lesson-authoring.md` | 那一節的「模考產生器」構想改成指向這份文件 |

## 8. 分階段

### 階段一：能用的最小版本

1. 建 `lessons/mock-exam.html`（獨立頁，含 `← 回目錄`、深色模式、字級）
2. 出題：漢字読み、文脈規定（規則見第 4 節）
3. 作答、對錯、說明、計分、`mockexam:wrong` 錯題紀錄
4. 「只考錯過的」複習模式
5. `python3 build-index.py`

**驗收標準**（照 `CLAUDE.md` 的通則）：

- [ ] 本機 `python3 -m http.server 4173` 開 `/lessons/mock-exam.html`，console 無 error
- [ ] 375px 手機寬度版面 OK、按鈕 ≥ 44px
- [ ] `python3 validate-lessons.py` 通過（含回目錄檢查）
- [ ] `python3 build-index.py` 跑過，`index.html` 出現這頁
- [ ] 連抽 30 題人工看過：沒有重複選項、沒有「兩個選項都對」、沒有明顯不是日文的干擾項
- [ ] 關掉再打開，錯題紀錄還在

### 階段二：用過之後調整

實際考幾輪，針對這些問題調規則：干擾項太好猜、兩個選項都講得通、名詞題偏簡單、副詞題干擾項重複。
需要的話補一份「排除組合」清單。**階段一沒做完不要先做這階段。**

### 階段三：補上要寫作的三種題型

1. 建 `data/exam-bank.json` 與對應的頁面邏輯
2. 開新 skill（暫名 `new-exam-questions`）：負責寫表記／言い換え類義／用法的題目、
   自我檢核、append 進題庫。**這時候才需要 skill**，因為到這裡才有「會重複做很多次」的流程。

## 9. 已知風險與未解問題

1. **題庫小**：140 字，考 20 題等於每次抽七分之一，重複率高。多做幾課才會耐考。
2. **干擾項品質靠人工把關**：程式沒辦法判斷「這個干擾項填進去其實也通」。階段一的驗收標準用人工看 30 題擋。
3. **名詞的漢字読み題偏簡單**（見 4.3）。
4. **這頁會出現在首頁目錄裡，跟課程並列**。它不是「一課」，但 `build-index.py` 一視同仁。
   目前靠 `<title>` 寫清楚「模擬考」來區分，沒有更好的做法（要區分就得改 `build-index.py` 的分類邏輯，
   為了一頁不值得）。
5. **純技術性修改會讓這頁在首頁跳到最上面**（日期規則是「最後 commit 日」），這是既有問題，不是這功能造成的。

## 10. 決策紀錄

| 決定 | 為什麼 | 否決的方案 |
|---|---|---|
| 獨立頁，不套引擎 | 模考沒有故事與文法表，套引擎要在 `lesson-engine.js` 加一堆 `if`，而動它要回歸測試每一課 | 做成引擎課薄殼 |
| 題庫不放 `data/lessons/` | `validate-lessons.py` 會用課程 schema 驗那個資料夾，放進去必報錯 | `data/lessons/exam.json` |
| 四選一的寫法照抄不共用 | 共用就得動 `assets/`，觸發全課回歸測試；照抄約 30 行，代價比較小 | 把 `gqRender()` 抽成共用元件 |
| 先做兩種程式出題的題型 | 不用先寫任何題庫，資料現在就有，做完馬上能用，也順便把頁面與計分定下來 | 五種一起做 |
| skill 留到階段三 | skill 是「重複做同一件事的說明書」。階段一是一次性開發，沒有可重複的流程可以寫 | 現在就開 skill |
