# 引擎課內容製作規範

`new-lesson` skill 依此規範產出 `data/lessons/<id>.json` + `data/vocab.json` 的新字 + `lessons/<id>.html` 薄殼。

## 命名

- `<id>`：**英數與連字號**，全小寫，取故事主題（`hospital`、`moving-house`、`train-trip`）。不要中文（網址才不會又長又亂碼）。
- `title`：故事標題（日文，會進 `<title>` 與首頁目錄顯示名）。skill 依故事想，於確認字表時一併提給使用者改。

## `data/lessons/<id>.json` schema

```jsonc
{
  "id": "hospital",
  "title": "父が倒れた日",
  "stories": [
    { "title": "篇一：父が倒れた日",
      "paragraphs": [ "…段落…", "…段落…" ], "translation": [ "…", "…" ] },
    { "title": "会話：病院の帰りに", "kind": "dialogue",
      "speakers": ["私", "母", "私"],
      "voices": { "私": "ja-JP-Neural2-D", "母": "ja-JP-Neural2-B" },
      "paragraphs": [ "…一句台詞…", "…", "…" ], "translation": [ "…", "…", "…" ] }
  ],
  "grammar": [
    { "point": "～てしまう", "example": "電気も消えてしまった",
      "meaning": "完成／帶遺憾語氣", "n4ref": "みん日II L29 / JLPT Sensei",
      "chunks": ["電気も","消えて","しまった"] }
  ],
  "grammarQuiz": [
    { "id": "gq-01", "g": 0, "s": "家に鍵を忘れて（　）。",
      "o": ["しまった","おいた","みた","いった"], "a": 0 }
  ],
  "reading": [
    { "id": "rq-01", "st": 1, "q": "父はどこで倒れましたか。",
      "o": ["部屋の隅","病院","庭","台所"], "a": 0,
      "ref": "父は部屋の隅で倒れていました。" }
  ],
  "passageQuiz": [
    { "id": "pq-01", "st": 2, "para": 3,
      "text": "…父（ちち）に（１）、…（２）…",
      "items": [ { "o": ["電話してもらって","電話してくれて","電話しておいて","電話してしまって"], "a": 0, "g": 3 },
                 { "o": ["でも","だから","それに","たとえば"], "a": 0 } ] }
  ]
}
```

- `stories`：3–7 篇（篇數 ≈ 目標單字數 ÷ 12；引擎不限篇數）。`stories[].title` 引擎會顯示在 `<h2>`；省略則顯示「篇N」。
- `stories[].translation`（**必填，每一篇都要**）：逐段中文翻譯，**陣列長度要跟 `paragraphs` 一樣**（逐段對應、每段不可留空）。引擎把它接在每段日文下面對照顯示。
  **翻譯標準**：日文一句對中文一句（可合併、不可漏）；台灣口語、不要翻譯腔（「記在了…上」「而居」）；
  **形容詞＋名詞不要照日文語序硬黏成詞**（「厳しい先生」✗「嚴格老師」→ ✓「老師很嚴格」或「很嚴格的老師」，故事開頭介紹人物時最容易中招）；
  文法點的語氣要留（てしまう＝不小心／結果…了、ておく＝先…起來、ようになる＝變得會…、のに＝明明…卻、たびに＝每次…都）；不加原文沒有的內容；中文字數約日文的 0.6–1.0 倍。
  `validate-lessons.py` 逐段檢查：字數比 < 0.45 或漏超過一句 → 報錯；句數不同、比例 > 1.4、出現翻譯腔字樣 → 提醒。
  （例外：`lessons/日文70單字學習器.html` 那類非引擎的舊課不適用。）
- `grammar`：對照表用。`n4ref` 必填、來源見 `docs/n4-grammar.md`。**`point` 要照抄清單標題**（進度用它當跨課 key；標「停用」的不能選）。
- `grammar[].chunks`（**必填**，新課由 skill 產）：把 `example` 切成 3–5 段，接起來要**剛好等於** `example`（驗證器比對）。這是「排序」練習（JLPT 文の組み立て）的題目。
- `grammarQuiz[].id`／`reading[].id`（**必填**）：`gq-01`…／`rq-01`…，同課唯一。進度用 `<課程id>/<題目id>` 當 key，**修題不改 id、刪題不重用編號**。
- `grammarQuiz[].g`：index 進 `grammar[]`（答完顯示該文法的說明）。`s` 一定含全形空格 `（　）`。`a` 是 `o` 的正解索引。干擾項優先取該文法點在 `docs/n4-grammar.md` 的「對比：」欄；沒有對比欄才用「同類但語意不合」的。干擾項不得使用清單外文法。
- `reading[].st`：故事序號（1 起，會話也算一篇）。`ref` 是文章依據句，答完會秀。
- **會話**（`stories[]` 裡 `kind: "dialogue"` 的那一篇，每課 1 篇、放最後、6–8 句）：一個 paragraph＝一句台詞，`speakers[]` 跟 `paragraphs` 一樣長，
  說話人不寫進台詞（語音才不會唸出名字）。`voices` 給每個說話人一個聲音，只能用 `ja-JP-Neural2-B`（女）／`-C`（男）／`-D`（男）／`ja-JP-Wavenet-A`（女）／`-C`（男），
  同一篇不同人不能重複。會話**不加新字、不教新文法**（只重組本課前面已經出現的字與文法點，驗證器擋）；用普通形／です・ます的分工練語體：朋友普通形、對老師或長輩です・ます。
  不算進「篇數 ≈ 字數 ÷ 12」，也不需要 `[[g#]]` 標記（有標的話只能標前面教過的）。讀解題可以出 2 題在會話上。
- **`passageQuiz`（文章文法，JLPT「文章文法」題型）**：每課 2 組、每組 3–4 格。`text` 是某篇某段（`st`、`para`，1 起）的原文，把要考的地方換成（１）（２）…（全形數字），
  注音與 `{{}}` 標記照留。空格優先挖本課文法點（`g` 指到 `grammar[]`），也可以挖接續詞（不填 `g`）。
  **正解填回去必須跟原段落一模一樣**（驗證器比對）；干擾項規則同克漏字，而且要在這個上下文裡**明確是錯的**（文法上勉強說得通的不要用）。
  `id` 用 `pq-01`…，進度 key 是 `<課程id>/pq-01#格`，修題不改 id。

## 故事段落標記

段落是**純字串**，兩種標記：

| 標記 | 意思 | 例 |
|---|---|---|
| `漢字（かな）` | 注音（全形括號）。**每個漢字詞都要標**（目標單字除外，見下） | `先週（せんしゅう）` |
| `{{key\|課文形\|讀音}}` | 目標單字（粗體、可點開詳解卡）。`讀音` 可省。`key` 不屬於本課（`lessons` 不含本課）＝**複習字**，引擎用虛線＋「復」顯示 | `{{倒れる\|倒れて\|たおれて}}` |
| `[[g<索引>]]…[[/g]]` | 文法點（該片語旁邊會有可點的角標，點開文法詳解卡）。`<索引>` 是 `grammar[]` 的 0 起索引，跟 `grammarQuiz[].g` 用同一套索引 | `[[g0]]通（かよ）うために[[/g]]` |

- `key` = `data/vocab.json` 裡該字的 `key`（通常＝辭書形）。
- **複習字**：之前的課學過的字，在這課故事裡自然再出現一次時照樣用 `{{key|課文形|讀音}}` 標起來（不用改 vocab.json）。每篇 1–3 個、全課 5–10 個；
  複習字不算新字（不佔每篇 10–13 個的額度、可以跟新字或新文法同一句），不進本課單字表與測驗，只在故事裡被點開複習。
- `課文形` = 該處實際出現的形（`倒れて`、`予約`…），**純文字不再加注音**。
- `讀音` = 對整個「課文形」的假名（會變 ruby 顯示在課文形上方）。
- 引擎解析順序：先抽 `{{…}}` 換佔位符登記，再把其餘 `漢字（かな）` 變 `<ruby>`。所以目標單字的注音走 `讀音` 欄，不走 `（かな）`。
- 引擎會把每段的 `translation` 接在該段日文下方（手機疊放、電腦左右對照），所以**翻譯要逐段對應、不要整篇合寫一段**。
- 音檔 key（`play()` 查的）= 段落去掉 `（かな）`、`{{}}` 取課文形、`[[g#]]`/`[[/g]]` 標記本身。skill 不用自己算。**下列四個地方必須一致處理，改析法時四個要一起改**（漏改會讓段落對不到音檔 key）：
  1. `generate-audio.py` 的 `clean_story_json()` —— 決定音檔 key 與檔名
  2. `build-audio-check.py` 的 `clean()` 與 `annotated()` —— 決定語音檢查表列不列得出這段
  3. `validate-lessons.py` 的 `plain()` —— 決定 `reading[].ref` 與音檔覆蓋率檢查
  4. `assets/lesson-engine.js` 的 `parsePara()` —— 決定網頁上按播放時查哪個 key

  會話的音檔 key 另外加上聲音：`@<聲音>:<乾淨文字>`（同一句話不同人說是不同音檔）。這條也是四處一致：
  `generate-audio.py` 的 `extract_pairs()`、`build-audio-check.py` 的故事迴圈、`validate-lessons.py` 的 `audio_key()`、`lesson-engine.js` 的 `renderStories()`。

## `data/vocab.json` 新字

```jsonc
{ "key": "倒れる", "dict": "倒れる", "reading": "たおれる",
  "pos": "自動詞", "zh": "倒下、病倒",
  "form": "本文：倒れて（て形）", "ex": "父が急に倒れてしまいました。",
  "lessons": ["hospital"], "jlpt": "N4", "exKana": "ちちがきゅうにたおれてしまいました。" }
```

- **`reading` 必須是 `dict` 的完整假名**（`散歩する`→`さんぽする`，不是 `さんぽ`）。這是引擎課單字卡音檔的合成來源，讀音才會 100% 正確。
- `pos`：`自動詞`／`他動詞`／`名詞`／`い形容詞`／`な形容詞`／`副詞`／`サ變動詞`／`接續詞`…（沿用舊課用語）。
- `zh`：中文意思，多個用「、」分隔（中→日測驗取第一個）。
- `form`：課文形註記（可留 dict 本身）。
- `ex`：一句例句，會進單字卡與音檔。
- 同一個字若多課共用 → `lessons` 放多個 id。（只是在別課故事裡再出現一次的話，當複習字就好，不用加 id。）
- `jlpt`（新課必填）：JLPT **參考**等級 `N5`／`N4`／`N3`／`N2`／`N1`，常用表以外的生活／專門用語填 `外`。官方沒公布單字表，依舊版出題基準與常見 N5–N1 單字表判斷；單字卡與單字表會顯示成小標籤。
- `exKana`（新課必填）：`ex` 的全假名寫法，標點照原句（助詞照寫法：は、へ）。「例句聽寫」拿它對答案，所以讀音要跟語音唸的一樣；有歧義的字（家＝いえ／うち）挑語音實際唸的那個。

## 驗收標準（skill 自我檢核用）

- 每課 **40–80 個目標單字**
- **3–7 篇故事**（篇數 ≈ 單字數 ÷ 12，70 字＝6 篇），每篇 **250–350 字**（日文字元；硬上限 400、下限 150）
- **難度控制**（讀者是 N5→N4，故事太難就讀不下去）：
  - 每篇新單字 **10–13 個**；全課約每 **20–25 字** 1 個新字；平均句長 ≤ 22 字
  - **一句一新**：同一句不同時放新單字與新文法點；新文法用學習者已會的動詞帶
  - 每篇最多 **2 個「新」文法點**（其餘標記為複習），每個文法點盡量在兩篇以上出現
  - 新單字只用辭書形（或 `form` 註記的形）與 て／た／ない／ます 四種變化，不用可能／受身／使役／條件／命令（除非該文法點本身就是它）
  - 文體：基底です・ます體，但**依用途混用**——內心話與朋友、媽媽的對話用普通形（放「」內）、老師用です・ます；句尾要有變化
    （〜ています／〜でした／體言止め／〜でしょう），同一種句尾不連續 3 句、現在式〜ます不連續超過 4 句、過去式〜ました類不超過 8 句；
    `～なければならない` 等驗證器詞幹對不上的，放進「」內用普通形
  - **不用清單外句型**（〜んです／〜のです／〜なんて／〜おかげで／〜ずつ 最常溜進來），只用 `n4-grammar.md` 與 N5 白名單
  - 固定人物、每篇一個場景；不為湊單字寫突兀的句子；日文要是日本人真的會這樣說的
- **至少 8 個 N4 文法點**（建議 8–12），每個都在 `docs/n4-grammar.md` 查得到；**沒教過的（`data/grammar.json` 裡 `lessons` 為空）佔 2/3 以上**，
  已教過的只當複習
- 每個目標單字在故事**至少出現 1 次**；`data/vocab.json` 的 `form` 註記與故事實際出現的形一致
- **複習字 5–10 個**（每篇 1–3 個，從之前的課挑，用在自然的句子裡）
- **會話 1 篇**（6–8 句、2–3 個說話人、每人不同聲音、不帶新字與新文法）＋翻譯；讀解另出 2 題在會話上
- **文章文法 2 組**（每組 3–4 格），正解填回＝原段落
- 每個新字都有 `jlpt` 與 `exKana`
- **自然度審查做過**：另派助手只看日文挑可疑句，採用／不採用都有理由
- 文法克漏字**每點 2 題**、讀解**每篇 5 題**
- 每個 `reading[]` 的 `ref` 真的是某篇故事裡的句子
- **每一篇故事都有 `translation`**，長度等於 `paragraphs`、每段都不空（不是只做第一篇）
- **每一篇故事都至少標到一個 `[[g#]]` 文法點**，且每個 `grammar[]` 文法點至少被標記一次（不是只標第一篇）
- **`[[g#]]` 包起來的範圍剛好是該文法的字樣**（`[[g4]]寝てしまった[[/g]]` ✓，包到不相干的句子 ✗）。
  `validate-lessons.py` 會自動比對；活用形類（受身形／使役形／可能形／疑問詞＋か／敬語）沒有固定字樣，
  腳本只會列 ⚠ 提醒，要人工確認
- **`grammar[].example` 本身要用到該文法**（同一套字樣比對）
- **同一課不放字樣一樣的兩個條目**（`～のに` 逆接＋目的、`～たら` 假定＋過去的發現、`～ように`、`～てくる／ていく`）
  ——驗證器分不出標記指哪一個，會報錯；要兩個都教就拆到不同課。
  `～そうだ` 樣態／傳聞是例外：接續不重疊（樣態接ます形、傳聞接普通形），驗證器分得出來，標錯會報錯
- 驗證器列出的 ⚠「字樣一樣，只能靠語意分辨」會指名「篇幾「哪段文字」」，**逐處人工確認**
- `<id>` 英數；薄殼有 `<title>` 與 `← 回目錄`
- 故事主題由這批單字內容決定

## 樣式／RWD／內容項目 —— 一律走引擎，不要自己刻

引擎課的外觀、互動、RWD 全部由 `assets/lesson.css` + `assets/lesson-engine.js` + `assets/vocab-table.js` 決定，薄殼不放任何自訂樣式。要調整外觀 → 改 `assets/`（會同時影響所有引擎課，改完要回歸測試每一課）。

引擎已內建：
- 主題 token（淺／`@media dark` / `[data-theme]` 三態）、⚙ 設定（主題、字級 `--fs`、語速、洗牌、清除本課紀錄、匯出／匯入進度）——設定全站共用（`store.js`）
- 精簡 sticky header（回目錄、標題、設定）；注音四態（全部注音／藏重點字注音／全部隱藏／遮住重點字）只在故事閱讀時顯示
- **底部固定分頁列**（拇指區、留 safe-area）：故事／單字表／單字測驗／文法；二級切換是細的 segmented control，不用卡片
- **每篇「下一步」流程**：篇名下 ①聽讀 ②跟讀 ③本篇單字 ④本篇文法 ⑤讀解，做完打勾（①② 記在 `progress.stories`，③④⑤ 從既有紀錄推算）；故事分頁最上面「幾篇完成・小考最高分」與「本課小考」
- **篇篩選**：單字表、單字測驗、克漏字、排序都能只看某一篇（單字＝第一次出現的篇，文法點＝第一次被 `[[g#]]` 標到的篇）
- 複習字（虛線＋「復」，卡片寫在哪一課學過）、JLPT 標籤、段尾「⋯」回報（設定裡可一次複製給 Claude）、會話版面（說話人、左右對話框）
- 故事：每篇「▶ 全篇」「跟讀錄音」與「日文／對照／中文」三態；逐段對照（手機疊放、≥1000px 左右雙欄）；「怎麼用這一課」可收合
- 單字表（two-row、整列可點）；單字卡有 Jisho 連結、例句跟讀錄音、我的筆記、評分
- 單字測驗（Anki 流程：顯示答案 → 評分鈕才出現、固定底部 → 自動下一題）：日→中（讀音要按才看）／中→日／聽力／例句聽力／漢字読み／表記（四選一）／中→日打字／單字聽寫／例句聽寫（打假名，系統標出不一樣的字、評分由自己決定）；篩選 全部／今日複習／未學過／已畢業
- 文法：對照表（整列可點開詳解卡，卡內有怎麼接／容易搞混／常見錯誤〔取自 `data/grammar.json`〕、N4 依據、複習狀態、筆記、文法清單連結）／克漏字（接 SRS，篩選 全部／今日到期／答錯）／排序（`chunks`）／文章文法（`passageQuiz`，有才顯示）
- 單課小考：`assets/mock-exam.js`，10 題（漢字読み 2、表記 2、文脈規定 2、克漏字 2、排序 1、讀解 1），執行時從本課資料組題，只記最高分
- 鍵盤：空白＝顯示答案、1/2/3＝評分、1–4＝四選一、→＝略過、P＝播放、Esc＝關閉
- 觸控目標 ≥44px、`@media (hover:hover)` 包 hover、iOS 輸入不放大（16px）、`@media print`
- 全部輸出經 `esc()`；音檔檔名先過 `/^[0-9a-f]{8,40}\.mp3$/` 才 `new Audio()`
- 進度與設定只透過 `assets/store.js`（`jl.settings.v1`／`jl.progress.v1`），跨課共用；引擎自己不碰 localStorage

## JLPT N4「文字・語彙」題型參考（出題手感用，不放實際題目）

補習班／學校課前小考常見的 N4 文字語彙小考，固定分五種題型。這裡只記「這題型在考什麼」，方便 `grammarQuiz` 出題或未來讀解題想干擾項時抓手感——**不要把任何補習班／教材的實際題目原文存進本檔或 repo**（版權不是我們的，且跨課綜合出題跟引擎「單課配單課單字」的模式對不上，見 `docs/mock-exam-plan.md`）。

| 題型 | 考什麼 | 對應到本站現有題型 |
|---|---|---|
| 漢字読み | 句子裡的漢字詞，選正確讀音（假名） | 單字測驗「漢字読み」（單字級，自動出題） |
| 表記 | 句子裡的假名詞，選正確漢字 | 單字測驗「表記」（單字級，自動出題） |
| 文脈規定 | 句子挖空，四選一選最合語境的詞（單字，非文法） | 接近 `grammarQuiz` 但那是文法點，這個是詞彙 |
| 言い換え類義 | 給一句話，選意思最接近的改寫句 | 目前沒有 |
| 用法 | 給一個詞，四個句子選用法正確的那句 | 目前沒有 |

現有 `grammarQuiz`（見上方 schema）是「文法點」克漏字，跟這五種「詞彙」題型是不同層次，不要混著塞同一個陣列。

跨課綜合的模考產生器是獨立功能，規劃在 `docs/mock-exam-plan.md`，不放進 `new-lesson` skill。

## 生成時要記得的實作細節

1. **TTS 會把多音漢字讀錯**（大分→だいぶ 被讀成 おおいた／大＋分）。引擎課單字卡改用假名合成已解決單字；例句／故事仍需 `docs/tts-notes.md` 的修正表 + audio-check 人工快篩。
2. **furigana 系統**：`漢字（かな）` + `{{}}` 佔位符，同一段能同時算出「純文字（對音檔）」與「含 ruby 的 HTML」。佔位符用 `@@T<n>@@`（純 ASCII，比隱形字元穩）。
3. **單字表是上下兩列**（第一列 單字/讀音/詞性/中文，第二列 例句整寬）——例句放同一列會被擠成一字一行。元件在 `assets/vocab-table.js`，勿改成單列。
4. **安全**：所有從 JSON 組出的 HTML（含屬性、aria-label）都要 `esc()`；`play()` 前驗證檔名 regex；localStorage 全 try/catch。
5. **檔案大小 / token**：共用引擎不複製進每課；版本歷程放 `docs/changelog.md`（AI 不載入）；CLAUDE.md 精簡、知識放 docs/ 用到才讀。
6. **回目錄連結**：`lessons/` 每頁都要有 `<a href="../">← 回目錄`。
7. **git 歷史**：音檔換內容才重產（檔名雜湊機制），別無謂整批重跑。
8. **billing**：Google TTS 需啟用帳單（免費額度內 $0），金鑰產完可停用，網站執行不需要。
