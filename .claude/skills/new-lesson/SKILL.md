# new-lesson：從單字生成一整份課程

先讀 `docs/lesson-authoring.md`（schema、標記、驗收標準）與 `docs/n4-grammar.md`（可用文法點）。
本專案慣例見 `CLAUDE.md`。步驟 2（確認字表）與步驟 9（聽 audio-check）要停下來等使用者回覆；commit 只在步驟 12 用 `publish.sh` 做一次。

---

## 步驟 1 — 讀單字輸入

- 使用者給的是**圖片**：仔細辨識每個單字。日文手寫／印刷都可能有相近字，不確定的先列出來問。
- 使用者給的是**文字**：直接解析。
- 每個字整理成：`辭書形 / 完整假名讀音 / 詞性 / 中文意思 / JLPT 參考等級`。
  - `讀音` 一定要是**辭書形的完整假名**（`予約する`→`よやくする`）。
  - `詞性` 用：自動詞／他動詞／名詞／い形容詞／な形容詞／副詞／サ變動詞／接續詞…
  - `JLPT 參考等級`：N5–N1，常用表以外的生活／專門用語標「外」（判斷依據見 `docs/lesson-authoring.md` 的 `jlpt`）。
  - 多音字（開、下、方、日、大…）先記下，步驟 8 要用。

## 步驟 2 — 跟使用者確認字表（停下來等回覆）

用表格列出「辭書形 / 讀音 / 詞性 / 中文 / 等級」，並：
- 標出你不確定的辨識或讀音，請使用者確認
- **N3 以上與「外」的字另外列出來**，說明「故事可能要硬塞、讀者也比較用不到」，問使用者要不要換掉或刪掉（使用者決定，字表是他給的）
- **提出這課的故事主題**（依這批單字內容判斷最合適的情境，例：醫院、搬家、購物、旅行），讓使用者改
- 提出建議的 `<id>`（英數連字號，取自主題）
- **提出分篇計畫**（篇數與每篇的場景、字，見步驟 4 的難度原則）：篇數 ≈ 單字數 ÷ 12；用固定的人物串成一條時間線，
  每篇一個場景，把**同主題的字放同一篇**。用表格列出「篇 / 場景 / 這篇的字」，讓使用者一起確認。
- **提出複習字**：從之前的課（`data/vocab.json` 裡 `lessons` 不含本課的字）挑 5–10 個放得進這次場景的字，排進分篇計畫（每篇 1–3 個）。
  在新的上下文裡再遇到學過的字，是記住它最有效的方式，所以挑讀者之後還會常用的字。使用者想指定就用他指定的。
- **提出會話設定**：場景（通常接在最後一篇之後）、2–3 個說話人、每人用哪個聲音（可用聲音見 `docs/lesson-authoring.md` 的會話規則；依性別、年齡分配，同一篇不能重複）。


## 步驟 3 — 挑 N4 文法點

- 從 `docs/n4-grammar.md` 挑 **至少 8 個**（建議 8–12 個）能自然融入這批單字情境的文法點。
- **優先選還沒教過的**：先跑下面這段，列出還沒被任何一課教過的條目（`lessons` 為空、非停用）。
  挑出的文法點裡，**沒教過的至少佔 2/3**；已教過的（如 ために、てくれる、ておく、てしまう、てもらう 這幾個每課都被挑的）只當複習、
  最多 1/3。若這批單字的情境真的放不進沒教過的，才多用已教過的，並在步驟 9 停下來時跟使用者說明。
  偏難的條目（受身、使役、敬語…）每課最多 2 個，放在後面的篇。

  ```bash
  python3 build-grammar.py     # 先更新「教過的課」
  python3 - <<'EOF'
  import json
  d = json.load(open('data/grammar.json'))
  un = [p for p in d['points'] if not p['lessons'] and not p['retired']]
  print(len(un), '條還沒教過（共', len(d['points']), '條）')
  for p in un: print(f"{p['section']}  {p['title']}")
  EOF
  ```
  （不需要另外維護「用過哪些」的表：紀錄就是各課 `data/lessons/*.json` 的 `grammar[].point`，`build-grammar.py` 每次自動彙整。）
- 不在那份清單的文法**不要用**（要用就先問使用者要不要補進清單）。標了「（停用…）」的條目也不能用，改用它指向的新條目。
- `point` 要**照抄清單的標題**（進度資料用標題當跨課共用的 key，寫法不同就對不到）。
- 每個記下 `point` / `meaning` / 對應的 `n4ref`（至少一個來源，如 `みん日II L29`）。
- `example` 要**真的用到那個文法**（驗證器會比對字樣，填一句不相干的會報錯）。
- 每個文法點加 **`chunks`**：把 `example` 切成 **3–5 段**（依文節切，含標點），接起來要**剛好等於** `example`。
  這是「排序」練習（JLPT 文の組み立て）的題目。例：`"chunks": ["窓を","開けた","まま","寝てしまった"]`。
- **同一課不要同時挑字樣一樣的兩個條目**（`～のに` 逆接＋目的、`～たら` 假定＋過去的發現、
  `～ように` 目的＋希望、`～てくる／ていく` ①＋②）——驗證器分不出標記指的是哪一個，會報錯。
  要兩個都教就拆到不同課。（`～そうだ` 樣態＋傳聞是例外，接續不重疊，驗證器分得出來。）

## 步驟 4 — 寫故事（3–7 篇，每篇約 12 個新單字）

讀者是 N5→N4 的學習者。故事太難就讀不下去，所以先守下面的**難度原則**，再談文法與標記。
主題與分篇就是步驟 2 敲定的計畫。

**難度原則**（複習字不算新東西：不佔新字額度，可以跟新字或新文法放同一句）

1. **篇數 ≈ 目標單字數 ÷ 12**（四捨五入，3–7 篇；70 字＝6 篇）。每篇新單字 **10–13 個**，同主題的字放同一篇。
   全課大約每 20–25 個日文字才出現 1 個新單字（更密就讀不下去）。
2. **每篇 250–350 日文字元**（硬上限 400、下限 150），平均每句 15–22 字，一句一件事，少用從屬子句疊在一起。
3. **一句一新**：一個句子最多只放**一種新東西**——本課新單字（第一次出現），或**新**文法點（該文法第一次出現），**不要同一句兩者都有**。
   （已經教過的文法點當複習，可以跟新單字放同一句。）
   要教新文法，就用學習者已經會的 N5 字、動詞來帶（「見ておく」「教えてくれる」）；新單字則放在沒有新文法的句子。
4. **新單字的形態**：第一次出現盡量用辭書形，或單字卡 `form` 註記的形；之後再出現可以換 **て形／た形／ない形／ます形** 這四種
   （讓學習者在別篇「再遇到、換個樣子」）。**不用**可能形、受身、使役、條件、命令，除非該文法點本身就是它。
5. **文法分配**：每篇最多 **2 個「新」文法點**（該點第一次出現），其餘標記都是複習；每個文法點盡量在**兩篇以上**出現。
   簡單的先教（篇一二），偏難的放後面的篇。
6. **文體：基底です・ます體（N5 最熟），但要有規則地混用，句尾不能一路「〜ます」到底**（全篇只有一種句尾，讀起來像教科書例句、不自然）：
   - **內心的話、感想用普通形，放在「」裡**：「今日も一番だ」と思いながら…／「よし、これで大丈夫だ」と思いました。
   - **對話依說話人決定**：朋友、媽媽對「我」講話用普通形（「おはよう、今日も早いね」）；老師用です・ます（「ゆっくりでいいですよ」）。
   - **句尾做變化**：〜ています／〜でした／〜ませんでした／〜でしょう／〜たい，加上**體言止め**（「電車で三十分。」「今日は体育の時間。」）；
     用「〜て、」「〜ながら」「〜ので」「〜と、」把兩句接起來，減少句數。
   - **不要沒理由地在同一段的地の文裡，一句です・ます、下一句だ・る**（日本人會覺得文體不統一）。混用只依上面兩種分工。
   - **句尾別單調**：同一種句尾不要一路連下去；每段 4 句以上時至少要有 1 個「非〜ます／〜ました」的句子（體言止め、でしょう、「」內心話擇一）。
     連續幾句的上限由 `validate-lessons.py` 算、會列 ⚠ 指出哪幾句，照它改。
   - 驗證器比對文法字樣時，`～なければならない` 的詞幹是「なければならな」，寫成「なければなりません」會比對失敗——
     這種文法放進「」內用普通形（例：`先生に「作らなければならない」と言われていました。`）。
7. **只用清單內的文法（`docs/n4-grammar.md`）與第 0 章 N5 白名單**：常見的溜進去的清單外句型有
   **「〜んです／〜のです」「〜なんて」「〜おかげで」「〜ずつ」**，要換成清單內的說法
   （〜からです、〜ので、〜と思います、〜て、）或別的字（「少しずつ」→「だんだん」、「一つずつ」→「順番に」）。
8. **連貫、不突兀**：固定人物（我、老師、朋友…）、每篇一個場景；用 N5 的熟字句子當上下文，讓生字有前後文可以猜。
   **不要為了湊字寫突兀的句子**。第一次寫不進去的字，放到最近的場景，寧可改場景，也別硬造句子。
9. 每個目標單字至少出現 1 次；選定的文法點每個至少用 1 次。

- 標記規則（見 `docs/lesson-authoring.md`）：
  - 一般漢字詞：`漢字（かな）`（全形括號）
  - 目標單字：`{{key|課文形|讀音}}`（`key` = vocab 的 key；`課文形` 純文字不加注音；`讀音` 是整個課文形的假名）
  - 複習字：一樣用 `{{key|課文形|讀音}}`，`key` 是舊課那個字的 key；不用改 `data/vocab.json`（引擎與驗證器從 `lessons` 判斷它是複習字）
  - **文法點**：步驟 3 選定的每個文法點，在它於故事裡出現的地方用 `[[g<索引>]]…[[/g]]` 包起來（`<索引>` = 該文法在 `grammar[]` 的 0 起位置，跟 `grammarQuiz[].g` 同一套索引）。
- 寫完自己念一遍：句子自然、文法用對、注音正確、**日本人會這樣說**（例：日本高中生不會說「日本語の本」，該說「英語の本」；
  情境裡的時間線要對得起來）。

**寫完先量一次難度**（超標就拆篇或刪填充，不要放著）：

```bash
python3 - <<'EOF'
import json, re
d = json.load(open('data/lessons/<id>.json'))
mine = {w['key'] for w in json.load(open('data/vocab.json')) if d['id'] in w.get('lessons', [])}
seen, total = set(), 0
for s in d['stories']:
    if s.get('kind') == 'dialogue':
        continue                      # 會話不帶新字，不算篇
    t = "".join(s['paragraphs'])
    keys = [k for k in re.findall(r'\{\{([^|}]+)\|', t) if k in mine]   # 複習字不算新字
    new = [k for k in dict.fromkeys(keys) if k not in seen]; seen |= set(keys)
    c = re.sub(r'\[\[/?g\d*\]\]', '', t)
    c = re.sub(r'\{\{([^|}]*)\|([^|}]*)(\|[^}]*)?\}\}', r'\2', c)
    c = re.sub(r'（[^）]*）', '', c)
    n = len(re.findall(r'[。！？]', c)); total += len(c)
    g = sorted({int(x) for x in re.findall(r'\[\[g(\d+)\]\]', t)})
    print(f"{s['title']}: {len(c)}字 {n}句 平均{len(c)/n:.1f}字/句 新單字{len(new)}個(每{len(c)/max(1,len(new)):.0f}字1個) 文法{g}")
print("全課", len(seen), "字 /", total, "字 → 每", round(total/max(1,len(seen))), "字1個新字")
EOF
```
目標：每篇 250–350 字、新單字 10–13 個、平均句長 ≤ 22 字、全課每 20–25 字 1 個新字。

### 每一篇都要做的兩件事

1. **`translation`**：逐段中文翻譯，陣列長度等於該篇的 `paragraphs`、每段都不可留空。
   **翻譯規範（引擎會把中文逐段接在日文下面對照，讀者是靠它理解句型，所以「完整」和「自然」都要）：**
   - **一句對一句**：日文有幾個「。」，中文就要有幾句（順序一樣）。可以把兩短句合成一句，**不能漏句**。
     最常見的錯是只翻第一句就換下一段——寫完一段回頭數一次句數。
   - **用台灣人平常講話的中文**，不要翻譯腔：
     ✗「把它記在了筆記本上」→ ✓「先記在手帳裡」；✗「決定一個人在外賃屋而居」→ ✓「決定一個人在外面租房子住」；
     ✗「房東太太說「…」笑了笑」→ ✓「房東太太笑著說：「…」」；✗「這是我久違地和家人以外的人打招呼」→ ✓「我好久沒有跟家人以外的人打招呼了」。
   - **形容詞修飾名詞，不要照日文語序硬黏成一個詞**：日文「い形容詞／な形容詞＋名詞」直接接在一起很自然（厳しい先生、忙しい一日），
     但中文的兩字形容詞＋名詞硬黏在一起，讀起來會像翻譯機，不是台灣人會說的話：
     ✗「嚴格老師問的問題不簡單」→ ✓「老師很嚴格，問的問題一點都不簡單」；
     ✗「忙碌一天終於結束了」→ ✓「忙了一整天，總算結束了」。
     判斷方法：把那個「形容詞＋名詞」單獨唸出來——聽起來像新聞標題或機器翻譯（而不是「這個老師很嚴格」那種正常說法），
     就該拆成兩句，或者至少加「的」（「很嚴格的老師」）。這條最容易在故事一開頭介紹人物時中招，寫完記得抓出每個「形容詞＋人物／地點」的地方單獨檢查。
   - **文法點的語氣要留在中文裡**（讀者要靠翻譯對照句型）：
     `～てしまう`＝「不小心／結果…了」、`～ておく`＝「先…起來／先…好」、`～ようになる`＝「變得會…／開始…」、
     `～たら`（發現）＝「一…就發現／一…，…就」、`～のに`＝「明明…卻」、`～たびに`＝「每次…都」、
     `～てもらう`＝「請（人）…」、`～てくれる`＝「（人）幫我…」、`～そうだ`（樣態）＝「看起來快要…」、`～たまま`＝「…著就」。
   - **不要加原文沒有的內容**，也不要把兩個意思壓成一句。中文字數大約是日文的 0.6–1.0 倍；低於 0.5 幾乎一定是漏翻。
   - 專有名詞用台灣慣用：玄関→大門／玄關、手帳→手帳、コンビニ→便利商店、大家さん→房東太太、下宿→租屋。
2. **`[[g#]]` 文法標記**：每篇故事至少標到一個文法點；而且 `grammar[]` 裡**每一個**文法點，都要至少在某篇故事被標記一次。同一個文法點在多處出現，可以每次都標。
   - **標記範圍要剛好包住那個文法的字樣**：`[[g4]]寝（ね）てしまった[[/g]]` ✓；包到隔壁不相干的句子 ✗。
     `validate-lessons.py` 會把包起來的字拿去比對該文法點的字樣，對不上就報錯（例：`[[g2]]` 指 `～ておく`，
     包起來的字裡卻沒有「てお」）。活用形類（受身形／使役形／可能形／疑問詞＋か／尊敬語謙讓語）沒有固定字樣，
     腳本比對不了，會列成 ⚠ 提醒，**這幾個要自己再看一次標對位置沒有**。

寫完全部故事後，**當場跑這段確認**（不要留到步驟 11）：

```bash
python3 - <<'EOF'
import json, re
d = json.load(open('data/lessons/<id>.json'))
marked = set()
for i, s in enumerate(d['stories'], 1):
    txt = "".join(s['paragraphs'])
    g = set(re.findall(r'\[\[g(\d+)\]\]', txt))
    marked |= {int(x) for x in g}
    tr = s.get('translation')
    need = s.get('kind') != 'dialogue'   # 會話不需要文法標記
    print(f"篇{i}: paragraphs={len(s['paragraphs'])} "
          f"translation={len(tr) if isinstance(tr, list) else '缺!'} "
          f"文法標記={sorted(int(x) for x in g) or ('缺!' if need else '（會話，不用）')}")
    # 每段：日文幾句／中文幾句／字數比。句數不同或比例 < 0.5 就是漏翻
    for pi, (p, t) in enumerate(zip(s['paragraphs'], tr if isinstance(tr, list) else []), 1):
        ja = re.sub(r'\[\[g\d+\]\]|\[\[/g\]\]', '', re.sub(r'（[ぁ-んァ-ヶ・ーゝゞ〜]+）', '', re.sub(r'\{\{[^{}|]+\|([^{}|]+)(?:\|[^{}]*)?\}\}', r'\1', p)))
        nj, nz = len(re.findall(r'[。！？]', ja)), len(re.findall(r'[。！？]', t))
        flag = '  ← 漏翻？' if (nz < nj or len(t) / max(1, len(ja)) < 0.5) else ''
        print(f"  段{pi}: 日 {nj} 句/{len(ja)} 字  中 {nz} 句/{len(t)} 字  比 {len(t)/max(1,len(ja)):.2f}{flag}")
miss = [i for i in range(len(d['grammar'])) if i not in marked]
print("沒被標到的文法點:", [f"g{i} {d['grammar'][i]['point']}" for i in miss] or "無")
EOF
```
每篇的 `translation` 要等於 `paragraphs`、每段都沒有「← 漏翻？」、每篇文法標記都不是「缺!」、最後一行是「無」，才算寫完。
然後**把每一段中文從頭唸一遍**，唸起來不像台灣人講話的句子當場改。

## 步驟 4b — 寫會話

在所有故事後面加一篇 `kind: "dialogue"`（格式見 `docs/lesson-authoring.md`），照步驟 2 敲定的場景與說話人：

- 6–8 句，一個 paragraph 一句台詞，`speakers` 逐句寫說話人、`voices` 給每人一個聲音；說話人不寫進台詞。
- 只用本課前面已經出現的字與文法點（驗證器會擋新東西）；可以順便用幾個複習字。
- 這篇的價值在語體：朋友之間普通形、對老師或長輩です・ます，讓讀者聽到故事裡較少出現的說話方式。
- `translation` 逐句寫，也是台灣口語。

## 步驟 5 — 出測驗

- **每一題都要有 `id`**：克漏字 `gq-01`、`gq-02`…，讀解 `rq-01`…，照順序編、兩位數。進度用 `<課程id>/<題目id>` 當 key，
  所以**日後修題目文字不要改 id、刪題後編號不重用**（驗證器會擋重複與缺 id）。
- **文法克漏字**：每個文法點 2 題。`s` 含 `（　）`，`o` 四選項，`a` 正解索引，`g` 指到 `grammar[]`。
  干擾項：該文法點在 `docs/n4-grammar.md` 有「對比：」欄 → 優先從對比欄所列文法挑（たら 的干擾放 と／ば／なら）；沒有 → 用「同類但語意不合」的（てしまう 的干擾放 ておく／てみる／ていく）。干擾項本身也必須是清單內或第 0 章 N5 白名單的文法，不得為湊選項用清單外文法。
- **讀解理解題**：**每篇故事固定 5 題**（6 篇＝30 題），會話另出 2 題。`st` = 篇序號（會話也算一篇），`ref` 必須是該篇裡真的有的句子。
- **文章文法 `passageQuiz`**：2 組、每組 3–4 格，各取自不同篇的一段（格式與規則見 `docs/lesson-authoring.md`）。
  挖的位置優先是本課文法點，也可以挖接續詞；每格干擾項要在上下文裡明確是錯的——文法上勉強說得通的選項會讓題目有兩個答案。
  `id` 用 `pq-01`、`pq-02`。

## 步驟 6 — 建檔

- `data/lessons/<id>.json`：`{id, title, stories[], grammar[], grammarQuiz[], reading[], passageQuiz[]}`，`stories[]` 每篇是 `{title, paragraphs[], translation[]}`（`translation` 見步驟 4），最後一篇會話多 `kind`、`speakers`、`voices`（見步驟 4b）
- `lessons/<id>.html` 薄殼（照 `docs/architecture.md`，`<title>` = `title`）：
  ```html
  <!DOCTYPE html><html lang="zh-Hant"><head>
  <meta charset="utf-8"><meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover">
  <meta name="color-scheme" content="light dark">
  <link rel="icon" href="data:image/svg+xml,%3Csvg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 16 16'%3E%3Ctext y='13' font-size='13'%3E%E3%81%82%3C/text%3E%3C/svg%3E">
  <title>【故事標題】</title>
  <link rel="stylesheet" href="../assets/lesson.css">
  </head><body>
  <div class="app" id="app" data-lesson="【id】"></div>
  <script src="../assets/store.js"></script>
  <script src="../assets/vocab-table.js"></script>
  <script src="../assets/lesson-engine.js"></script>
  </body></html>
  ```
  （`store.js` 一定要在 `lesson-engine.js` 前面，引擎靠它讀寫進度與設定。）

## 步驟 7 — 加字進 `data/vocab.json`

- 每個字一筆：`{key,dict,reading,pos,zh,form,ex,lessons:["<id>"],jlpt,exKana}`
- `reading` = `dict` 的完整假名；`ex` 一句例句（可從故事挑一句改短）
- `jlpt` 用步驟 2 確認過的等級；`exKana` 是 `ex` 的全假名寫法（標點照原句，例句聽寫拿它對答案，讀音要跟語音一致）
- **`form` 註記要跟故事實際出現的形一致**（`本文：運びました（ます形）／運んで（て形）`）。故事事後改過，這欄也要回頭對一次
  （單字卡會顯示它，對不上會誤導）。
- append 到陣列尾，保持 JSON 合法（結尾換行）

## 步驟 7b — 自然度審查

用 Agent 工具另派一個助手，只給它這課的日文（故事、會話、文章文法題與干擾項、例句與 `exKana`）、人物設定，
以及讀者程度（N5→N4）和本課選用的文法點清單（這些都在範圍內，不算超綱），請它列出：
日本人不會這樣說的句子、語體不對的台詞、有兩個答案的文法題、`exKana` 讀錯的地方——附理由與嚴重度，**只挑錯、不改檔**。
自己寫的東西自己檢查容易看不出來，所以交給沒參與寫作的助手。回來後逐條判斷：採用就改（連同翻譯、`reading[].ref`、`form` 一起），不採用記下理由；
結果在步驟 9 停下來時一起告訴使用者。

## 步驟 8 — 預填發音修正表

- 掃故事段落、會話與例句裡的**多音漢字**，比對 `docs/tts-notes.md` 的清單。
- 該處讀音非最常見者 → 在 `generate-audio.py` 開頭加一行：
  - 詞（≥2 字、不誤傷其他詞）→ `READING_FIXES`（長詞放前面）
  - 單一漢字、整段剛好是它 → `EXACT_FIXES`
- 單字卡本身不用管（引擎課已用假名合成）。

## 步驟 9 — 產語音

**先確認金鑰**：`tts-key.txt` 存在且非空（或有 `GOOGLE_TTS_API_KEY`）。沒有就**停下來**請使用者放：
```bash
printf '%s' '你的金鑰' > tts-key.txt
```
（`.claude/hooks/require-tts-key.sh` 也會在沒金鑰時擋下 `generate-audio.py` 並提醒。）

```bash
python3 generate-audio.py      # 只會產這課的新段落，並把清單寫到 audio/last-run.json
python3 build-audio-check.py   # 預設只列「本次新增」那批
```
- 若回 `BILLING_DISABLED` → 停下來，請使用者到 Google Cloud 啟用帳單（見 `docs/tts-notes.md`）。
- 產完**請使用者開 audio-check.html 聽「本次新增」那批**（舊的之前已經聽過，不用重聽），把 ✗ 的字回報 → 補修正表 → 重跑。
  會話那幾段標「會話」與說話人，順便請使用者確認聲音聽得出是不同人。

## 步驟 10 — 重建目錄

```bash
python3 build-index.py
python3 build-grammar.py     # 文法查詢頁的「教過的課」會多出這一課
```
確認新課以 `title` 出現在 `index.html`「開始學」區（卡片會顯示 字數／文法點數／篇數／＋會話）。

## 步驟 11 — 自我檢核

**先跑自動驗證**（會擋掉大部分結構錯誤）：
```bash
python3 validate-lessons.py <id>
```
沒過就照訊息修，過了再往下人工檢查。

逐項打勾，不過就修：

內容（對照 `docs/lesson-authoring.md`）：
- [ ] 目標單字 40–80 個；每個在故事至少出現 1 次
- [ ] 篇數 ≈ 單字數 ÷ 12（3–7 篇）；每篇 250–350 字（硬上限 400、下限 150）；每篇新單字 10–13 個（步驟 4 的量測腳本跑過）
- [ ] 難度原則：新單字只用辭書形／て／た／ない／ます（一句一新、文體見下面兩項）
- [ ] ≥8 個文法點，**每個都能在 `docs/n4-grammar.md` 找到**（驗證器會擋）；其中還沒教過的佔 2/3 以上（步驟 3 的指令查過）
- [ ] 克漏字每點 2 題、讀解每篇 5 題＋會話 2 題；每個 `reading[].ref` 真的在對應故事裡
- [ ] 複習字 5–10 個、每篇 1–3 個，用在自然的句子裡（驗證器少於 5 個會提醒）
- [ ] 會話 6–8 句、每人不同聲音、語體分工對（朋友普通形、對老師です・ます）、沒有新字新文法（驗證器擋）
- [ ] 文章文法 2 組、每組 3–4 格，驗證器確認正解填回＝原段落；每格干擾項在上下文裡明確是錯的
- [ ] 每個新字有 `jlpt` 與 `exKana`；N3 以上的字在步驟 2 問過使用者
- [ ] 步驟 7b 的自然度審查做過，採用／不採用都有理由
- [ ] 日文自然、日本人真的會這樣說（人物身分、時間線對得起來）；`data/vocab.json` 的 `form` 註記跟故事實際出現的形一致
- [ ] **文體與句尾**：基底です・ます、內心話與朋友／媽媽的話用普通形、句尾有變化（驗證器列的句尾 ⚠ 都處理過）；沒有清單外句型（〜んです／〜のです／〜なんて／〜おかげで／〜ずつ）
- [ ] **一句一新**：驗證器列的「一句兩新」⚠ 都處理過（敬語類單字本身就是文法點的，可以留）；每篇新文法 ≤2
- [ ] **中文翻譯逐段重讀一遍**：句數與日文一致；台灣口語；語氣詞不重複疊加（「大概…吧」擇一）；不拗口的名詞片語（「我們所受的教育」→「我們的教育」）；不加原文沒有的內容
- [ ] 每個 `grammarQuiz[].g` 指到正確的 `grammar[]` 項目（答完顯示的說明對得上題目）
- [ ] 每題都有 `id`（`gq-NN`／`rq-NN`）且不重複；每個 `grammar[]` 都有 `chunks`，接起來等於 `example`
- [ ] `data/vocab.json` 每個新字 `reading` = `dict` 完整假名
- [ ] **每一篇**故事都有 `translation`，長度跟 `paragraphs` 一樣、每段非空
- [ ] **每一段**翻譯句數跟日文一樣（合併可以、漏句不行）、字數比 0.6–1.0、唸起來是台灣口語、文法點的語氣有留在中文裡（驗證器會擋明顯漏翻、提醒句數不合與翻譯腔）
- [ ] 翻譯裡沒有「形容詞＋名詞」照日文語序硬黏的痕跡（例：「嚴格老師」這種）——這條驗證器抓不到，只能人工唸一遍
- [ ] **每一篇**故事都至少標到一個 `[[g#]]…[[/g]]`；`grammar[]` 每個文法點都至少被標記一次，`#` 對到正確索引
- [ ] 驗證器列出的 ⚠ 全部處理過：
  - 「無法自動比對標記位置」（活用形類）→ 人工確認標的位置正確
  - 「字樣一樣，只能靠語意分辨」→ 照它列出的「篇幾「哪段文字」」逐處確認條目沒指錯

檔案／技術：
- [ ] `<id>` 英數連字號；薄殼有 `<title>` 與（引擎會自動加的）`← 回目錄`
- [ ] 本機 `http.server`，開 `/lessons/<id>.html`：底部四分頁都在、故事注音正確、目標字與複習字可點開詳解、單字表 two-row 有等級標籤、
      每篇 ①→⑤ 流程按了會打勾、篇篩選有用、單字測驗九種模式（含打字與兩種聽寫）可作答、
      文法四分頁（對照表／克漏字／排序／文章文法）可用、會話聲音對、本課小考能做完、設定可換主題/字級/語速
- [ ] 故事卡的「日文／對照／中文」可切換、文法角標點得開（內容對得上 `grammar[]`）
- [ ] 首頁「今天要複習」與 `review.html` 看得到這一課的字（練過幾個字後到期就會出現）
- [ ] `read_console_messages` 無 error
- [ ] `resize_window` 375px：手機版 OK
- [ ] 進度與設定只寫在 `jl.progress.v1`／`jl.settings.v1`（透過 `assets/store.js`），沒有其他 localStorage key
- [ ] audio-check 聽過、無誤讀

## 步驟 12 — 發佈

```bash
./publish.sh "新課程：【title】"
```
（`validate-on-publish` hook 會在這裡再驗一次 JSON，沒過會擋下。）
告訴使用者：Pages 1–2 分鐘後更新，總單字表會自動出現這課、首頁目錄多一個連結（顯示名＝故事標題）。
